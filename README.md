# 📄 Документация проекта `feeldown-backend`

## 1. Общее описание

`feeldown-backend` — это серверная часть социального приложения
«Бэкенд после пьянки» (BAD-архитектура). Проект построен на **NestJS**
с использованием **Prisma ORM**, **Passport.js** для
OAuth2-аутентификации (Google, GitHub) и поддерживает классическую
регистрацию по паролю. Кодовая база организована по модульному
принципу, каждый модуль отвечает за свою предметную область.

---

## 2. Ключевые технологии

| Технология          | Назначение                                                                 |
| ------------------- | -------------------------------------------------------------------------- |
| **NestJS**          | Фреймворк для построения эффективных и масштабируемых серверных приложений |
| **Prisma**          | ORM с типами, миграциями и автогенерацией клиента                          |
| **Passport.js**     | Стратегии OAuth2 (Google, GitHub) и сессионная аутентификация              |
| **PostgreSQL**      | Основная база данных                                                       |
| **Docker**          | Контейнеризация приложения и базы данных                                   |
| **JWT / bcrypt**    | Генерация токенов и хеширование паролей                                    |
| **Swagger**         | Документация API (OpenAPI v3)                                              |
| **Fock-logger**     | Кастомный логгер для структурированного логирования                        |
| **Class-validator** | Валидация входящих DTO                                                     |

## 3. Архитектура проекта

### 3.1 Модульная структура

Проект разделён на несколько модулей, каждый из которых решает свою
задачу:

```
src/
├── app.module.ts               # Корневой модуль
├── main.ts                     # Точка входа
├── swagger.ts                  # Генерация Swagger-документации
├── database/                   # Prisma-схема и сервис
├── services/                   # Общие сервисы (логгер, env)
├── utils/                      # Утилиты
├── decorators/                 # Кастомные декораторы
├── pipes/                      # Глобальные пайпы
├── enums/                      # Перечисления
├── errors/                     # Фабрики ошибок
├── types/                      # Глобальные типы
└── v1/                         # Версия API v1
    ├── constants/              # Константы
    ├── dto/                    # Общие DTO
    ├── entities/               # Сущности (для Swagger)
    ├── enums/                  # Специфичные для v1 перечисления
    ├── errors/                 # Ошибки модулей
    ├── guards/                 # Guards (AuthGuard, OnlyMeGuard)
    ├── handlers/               # Обработчики метаданных и исключений
    ├── interceptors/           # Интерцепторы (кэширование)
    ├── middlewares/            # Мидлвары
    ├── pipes/                  # Пайпы (валидация slug, username)
    ├── services/               # Сервисы (Crud, Hash, ServerUser)
    ├── strategies/             # Passport-стратегии
    ├── routes/                 # Модули предметных областей
    │   ├── auth/               # Аутентификация
    │   ├── users/              # Пользователи
    │   ├── posts/              # Посты
    │   ├── notifications/      # Уведомления
    │   ├── friendships/        # Дружба (заявки)
    │   ├── follow/             # Подписки
    │   └── block/              # Блокировки
    └── ...
```

### 3.2 Основные модули

| Модуль            | Описание                                                                    |
| ----------------- | --------------------------------------------------------------------------- |
| **Auth**          | Регистрация, логин, OAuth2 (Google/GitHub), получение текущего пользователя |
| **Users**         | Управление профилем (CRUD)                                                  |
| **Posts**         | Создание, редактирование, удаление, получение постов                        |
| **Notifications** | Система уведомлений (комментарии, реакции, дружба)                          |
| **Friendships**   | Заявки в друзья (статусы: PENDING, ACCEPTED, REJECTED)                      |
| **Follow**        | Подписки (follower/followee)                                                |
| **Block**         | Блокировка пользователей (автоматически удаляет подписки и дружбу)          |

## 4. Запуск проекта

### 4.1 Локальный запуск (без Docker)

```bash
# Установка зависимостей
pnpm install

# Генерация Prisma клиента
npx prisma generate

# Накат миграций
npx prisma migrate deploy

# Запуск в режиме разработки
pnpm run start:dev

# Запуск в production
pnpm run build
pnpm run prod
```

### 4.2 Запуск через Docker Compose

```bash
# Поднять контейнеры (postgres + app)
docker-compose up -d

# Остановка
docker-compose down
```

Контейнер `app` автоматически выполнит миграции при старте.

## 5. Переменные окружения

Основные переменные (полный список в `.env`):

| Переменная                                                  | Назначение                           |
| ----------------------------------------------------------- | ------------------------------------ |
| `DATABASE_URL`                                              | Строка подключения к PostgreSQL      |
| `SESSION_SECRET`                                            | Секрет для express-session           |
| `HASH_KEY`                                                  | Ключ для JWT                         |
| `TOKEN_EXPIRATION`                                          | Время жизни токена (например, `28d`) |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`                  | OAuth2 Google                        |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`                  | OAuth2 GitHub                        |
| `CALLBACK_URL`                                              | URL для редиректа после OAuth2       |
| `CLIENT_URL`                                                | URL фронтенда (для CORS)             |
| `PORT`                                                      | Порт приложения (по умолчанию 8080)  |
| `ENCODING_TYPE`                                             | Кодировка токена (hex/base64)        |
| `THROTTLER_LIMIT`, `THROTTLER_TIME_TO_LIVE_IN_MILLISECONDS` | Ограничение запросов (throttler)     |

## 8. Модель данных (Prisma)

Основные модели:

- **User** — пользователь (username, nickname, описание)
- **Auth** — данные аутентификации (email, пароль, JWT)
- **Service** — OAuth2-сервисы (Google, GitHub)
- **Post** — пост (заголовок, содержание, postname)
- **Comment** — комментарий (иерархический)
- **PostReaction / CommentReaction** — реакции (лайки)
- **Follow** — подписки
- **FriendRequest** — заявки в друзья (PENDING → ACCEPTED/REJECTED)
- **Block** — блокировки (удаляет подписки и дружбу)
- **Notification** — уведомления (типы: реакция, комментарий, дружба)

Связи и индексы оптимизированы для быстрых запросов.

## 9. Утилиты и декораторы

### Декораторы

- `@Public()` — открытый эндпоинт (пропускает `AuthGuard`)
- `@OnlyMe(parameter)` — доступ только владельцу ресурса
- `@Me()` — внедрение текущего пользователя
- `@Queries(DTO)` — валидация query-параметров
- `@UserFindOptions(parameter)` — парсинг slug (`.username` или
  `~postname`)

### Пайпы

- `UsernameSlugPipe` / `PostnameSlugPipe` — преобразуют `.username` →
  `{ id? , username? }`
- `ResolvedSlugToIdPipe` — получает ID по username
- `MePipe` — достаёт пользователя из запроса

## 10. Обработка ошибок

Используется `FockerorFactory` из пакета `fockeror` для
централизованного создания исключений с понятными сообщениями и
HTTP-статусами. Все ошибки перехватываются глобальными фильтрами
(`DefaultExceptionFilter`, `PrismaExceptionFilter`).

---

## 11. CI/CD

При пуше в ветку `main` или `main--code-refactoring`:

1. Устанавливаются зависимости
2. Генерируется Prisma клиент
3. Запускается `pnpm run swagger`
4. Сгенерированные JSON-файлы копируются в `public/`
5. Деплой на GitHub Pages (ветка `gh-pages`)

## 12. Заключение

Проект построен с учётом **чистой архитектуры** и **модульности**, что
упрощает расширение и поддержку. Вся логика разделена по слоям:
контроллеры → сервисы → репозитории (Prisma). Присутствуют guards,
interceptors, pipes и middleware для обработки запросов. Документация
всегда актуальна благодаря автоматической генерации Swagger.
